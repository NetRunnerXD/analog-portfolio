## 1. Grid

| Property | Value |
|---|---|
| Resolution | 0.5° × 0.5°, 720 columns × 360 rows, **identical for Earth, Moon and Mars** |
| Longitude | **−180..180, east-positive** on all three bodies (roll PDS 0–360 products by half the width) |
| Cell size | 0.5° ≈ **55.6 km north–south** but only **≈ 55.6·cos(lat) km east–west** (≈ 56 × 12 km at 77.5°S, ≈ 55 × 33 km at 54°N). Cells are not squares away from the equator; area ∝ cos(lat) |
| Registration | **Cell centre**. Column centres −179.75 … 179.75; row centres 89.75 … −89.75 |
| Row order | North to south (row 0 = 89.75°) |
| Cell ID | `cell_id = row * 720 + col`, `col = floor((lon + 180) / 0.5)`, `row = floor((90 − lat) / 0.5)`, clamped to 719 / 359; range 0…259199 |
| Aggregation | Derivatives (slope, ΔT, PSR fraction, relief) computed at native resolution **first**, then aggregated: `average` for continuous fields, mode / class fraction for categorical. **cos(lat) area weights** for every land fraction, Earth percentile and median, P0.5/P99.5 clip, top-5%/top-1% threshold and validation percentile. All distances (NMS, "> 300 km from a known analog") are **great-circle** (haversine, body radius; canonical Earth radius **6371.0088 km**, IUGG mean radius, in both Python and JS) |
| Earth search space | Land cells only (`water_frac < 0.5`), shipped **sparse** (cell_id column) |
| Moon/Mars grids | Shipped **dense** (all 259200 cells in cell_id order) for reverse search and the twin viewer; **targets never come from these grids** (polar degeneracy). Target vectors are window summaries from native-resolution products around the anchor (`sample_radius_km`: Moon 15, Mars 25), see §6 |

### 3.1 Normalization rules (per-factor similarity s ∈ [0, 1])

| Rule (`normalization`) | Formula | Used by |
|---|---|---|
| `ratio` | `s = 1 − |x − t*| / (x + t*)` (ESI form, Schulze-Makuch 2011 [R80]); `s = 1` if both are 0 | F5 |
| `range_normalised` (v1.2) | `s = max(0, 1 − |x − t*| / (P99 − P1))`, P1/P99 = cos(lat) area-weighted Earth land quantiles of that factor; t* = target clipped to Earth P0.5…P99.5. Replaces the ESI ratio for temperature, which stayed ≥ 0.8 almost everywhere once a Moon target was clipped to Earth's coldest cell | F1, F2 |
| `ordinal_class` | Within-body percentile → 5 classes (edges P20/P40/P60/P80): 1 dusty, 2 fine, 3 sandy, 4 blocky, 5 rocky. `s = 1 − |Δclass| / 4`. Raw units never pooled across bodies | F3 |
| `bounded_fraction` | `s = max(0, 1 − |x − t|)` | F4, F8, F9 |
| `categorical_matrix` | `s = M[lith_earth, lith_target]` from the symmetric matrix in `factors.json` (same class 1; listed pairs e.g. basic plutonic ↔ anorthositic highland 0.8, basalt ↔ intermediate volcanic 0.5; others 0; no-data 0) | F6 |
| `directional_percentile` | `s = 1 − P_earth(x)` (drier = better), P = within-Earth **area-weighted** percentile rank in [0, 1]: (weight below + ½ weight of equal values) / total weight | F7 |
| `gaussian` | `s = exp(−½((x − t*)/τ)²)`, τ = 5° | F10 |
| `capped_directional_percentile` | `s = c_body × P_dir(x)`. F11: P_dir = mean of within-Earth percentiles of lower column mass and lower cutoff rigidity; caps c = 0.10 (Mars), 0.006 (Moon). F12: P_dir = percentile of higher UV; caps c = 0.006 (Mars), 0.005 (Moon) | F11, F12 |
| `flag_match` | `s = popcount(flags_earth & flags_target) / popcount(flags_target)` (0 if the target has no flags) | F13 |

**F1/F2 after the clip (intended, review M3):** for targets beyond Earth's range every target rewards closeness to the same Earth extreme (F2 t* = P99.5 for all 18 targets; F1 t* = P0.5 for 15 of 18), and cells more than one Earth P1–P99 span from t* score s = 0, i.e. the 0.01 floor of the geometric mean. The share of land at s = 0 per target is exported in `targets.json → scoring_constants.range_norm.zero_share_of_land`. Degenerate span (P1 = P99): s = 1 on an exact match, else 0.

**Earth-achievable clip** (factors with `earth_clip = yes`: F1, F2, F5, F10): `t* = clip(t, Earth P0.5, Earth P99.5)` over land cells (cos(lat) area-weighted quantiles); `gap = |t − t*|` is always computed on the **unclipped** target and is stored in `targets.json` and in every site's `gaps`, and shown next to the score.

### 3.2 Aggregation

1. **Hard filters**: global (`land`: `water_frac < 0.5`; `not_urban`: `builtup_frac < 0.5`) plus per-profile filters (§4). Filtered cells get S = 0.
2. **Core**: `S_core = Π max(s_i, 0.01)^(w_i / Σw)` over F1–F10 with `w_i > 0` (weighted geometric mean; one bad factor can't hide).
3. **Secondary nudge**: `S = S_core × (0.9 + 0.1 × S_sec)`, `S_sec` = arithmetic mean of F11–F13. Capped factors can only break ties.
4. **Logistics** is a separate axis, never similarity and never a cost weight (v1.1): it is the `easiest_to_reach` hard filter on the candidate pool (`travel_time_min ≤ 360`, MAP travel time to the nearest city of 50k+) and the access line on site cards.
5. **Missing target value**: target `null`s are filled by sampling the native product in the pipeline. A weighted core factor still without a value (F3 for the polar Moon targets: Diviner rock abundance stops at 60°) is dropped for that target and the remaining weights renormalised; `targets.json → targets[].dropped_factors` lists every target-dependent factor still without a value (F7, F11 and F12 use only Earth values and are never dropped this way) and portfolios list the weighted ones in `dropped_factors`. Never a crash.
6. **Missing Earth value** (per cell): a factor whose Earth input is NaN in a cell is dropped for that cell and the active weights renormalised over the factors present. The cell is scored only if the present factors carry **≥ 70% of the profile's active weight**; otherwise it is flagged `insufficient_data` and excluded from ranking, thresholds, candidate pools and robustness (it is neither a hit nor counted in the land total). "Active" weight = profile weight > 0 and not dropped for the target; exactly 70% counts as enough. A missing factor score is exported as `null` in `factor_scores` and never covers a factor in set cover. Each site carries `data_coverage` (share of the active weight present in its cell), each portfolio `insufficient_cells` (count of flagged cells), and validation sites in flagged cells get no result for that pair.
7. **Ties** (canonical, shared by Python and the Worker so candidate IDs match exactly): within-Earth percentiles use mid-ranks (tied values share one percentile; cell order never matters). Candidate selection is a **stable sort by factor score s_f desc, then total S desc, then cell index asc** (index in `earth_features`, which is `cell_id` order); the set-cover pool is ordered by S desc, then cell index asc; greedy ties go to the earliest site in pool order. Scores are computed on the decoded (quantized) `earth_features` values.
8. **Mars gate** (v1.2, `profiles.json → defaults.candidate_gates.mars`, Researcher `docs/research.md §8`): for **every profile of a Mars target (P1–P5, including P5)**, after the land (`water_frac < 0.5`) and built-up (`builtup_frac < 0.5`) filters, a cell passes if ANY of: **(A)** `aridity_index ≤ 0.20`; **(B)** `barren_frac ≥ 0.50`; **(C)** `permafrost_frac ≥ 0.50` AND `barren_frac + moss_lichen_frac ≥ 0.50`; **(D)** `geomorph_flags & 65` (impact bit 1 or Holocene-volcanic bit 64, **not** massif) AND (`aridity_index ≤ 0.50` OR `barren_frac ≥ 0.10`). Missing: NaN AI fails A and the AI part of D; other NaN read as 0. Cells failing the gate score S = 0, cannot be candidates, and **leave the ranking**: they are excluded from the Earth-percentile population, the top-5% / top-1% thresholds and the Monte Carlo population (percentile 0). Profile hard filters keep the S = 0-in-population rule. The former P5-only `dry_or_cold_desert` filter is dropped. **Provenance (honest disclosure):** the gate was designed after the first validation run, using the 15 Mars-relevant analogs and 11 negative controls of `docs/validation.csv`, and before the validation freeze; for those sites validation is therefore not blind with respect to the gate. Known exception: Rio Tinto fails (sub-cell acid river in semi-arid woodland) and is reported as `gate_excluded`, not whitelisted.
9. **Not scored**: gravity, vacuum, Earth visibility. They appear on the Fidelity Gap panel / target card only.

### 3.3 Lithology codes (F6) and geomorphic flags (F13)

Lithology codes 0–15 follow GLiM's first-level classes (nd, vb, vi, va, pb, pi, pa, mt, ss, sm, sc, ev, su, py, ig, wb); 16 = anorthositic highland regolith (Moon), 17 = impact breccia / melt. Flags are a bitmask: 1 impact, 2 lava tube / cave, 4 periglacial, 8 debris-covered glacier / buried ice, 16 massif / ridge crest, 32 permanent shadow / cold trap, 64 volcanic field. Full tables in `contract/factors.json`.

### 4.1 Portfolio variants and robustness (v1.1)

| Variant `id` | UI | Candidate pool | Set cover |
|---|---|---|---|
| `best_match` | Best match | full pool (§2.5 of plan.md) | greedy, gain = Σ w_f·s_f over newly covered factors |
| `easiest_to_reach` | Easiest to reach | **hard filter** `travel_time_min ≤ 360` (≤ 6 h to the nearest city of 50k+, MAP raster value of the cell; cells with no value excluded) | same greedy, no cost term |
| `one_continent` | One continent | pool restricted to one continent (`earth_features.continent`, Natural Earth admin-0 `CONTINENT` of the cell); every continent is tried, the one with the highest covered weight wins (ties → higher summed S) | same greedy |

Each variant is exported with `available`, `unavailable_reason` (UI copy), `continent`, `pool_size`, `sites`, `covers`, `coverage`. The UI compares `covers` across variants for the "No single continent covers {k} or more needs" message. The v1.0 λ-cost variants (`fidelity`/`balanced`/`accessible`/`single-continent`) are gone.

**Robustness:** for each (target, profile), 1000 Dirichlet draws (α_i = 50·w_i/Σw over the active weighted core factors only, so α0 = 50; zero-weight and dropped factors stay at 0; numpy PCG64, seed 20261114, generated offline and shipped); per draw, S is recomputed for every scorable land cell (filtered cells S = 0, `insufficient_data` cells excluded) with a chunked float32 log-space matmul, the **area-weighted P95 of S over land** is the top-5% threshold, and a cell scores a hit if S ≥ threshold. `robustness.top5_freq` = hits / 1000 is exported for every site in `variants[].sites` and `top_cells` (and in `sites/*.json → best_for[]`); `robust = top5_freq ≥ 0.8`. Precomputed for default weights only (the UI hides it under custom weights). Each portfolio also carries `earth_thresholds{median, top5, top1}` (area-weighted land quantiles of S at default weights).

### 5.1 Binary column store

Arrays are concatenated in manifest order; each starts at a 4-byte-aligned `byte_offset` and holds `length` values of `dtype`. `physical = raw × scale + add_offset`; `raw == nodata` means missing (255 for uint8, 65535 for uint16). The manifest also carries per-column stats (P0.5, P50, P99.5, min, max) used for the Earth clip. Decoders: `pipeline/analog_portfolio/grid/binary.py` (`read_grid`) and `web/src/data.ts` (`loadGrid`).

Manifests carry `grid`, `subset` and `companions`. Targets never come from these grids.

## 7. Validation (blind rediscovery)

Input: `docs/validation.csv` (Researcher) with columns `name, lat, lon, body_analog (moon|mars|both|none), mission_purposes (';'-separated profile IDs or 'none'), why, citation_url`. 21 positives, 11 negative controls (`body_analog = none`, including NEEMO as an operations-only analog). A positive is evaluated for every target whose body matches `body_analog` (`both` = either) and every profile in `mission_purposes`; negatives are evaluated for every (target, profile) pair. Percentiles are cos(lat) area-weighted mid-ranks of S among Earth land cells (hard-filtered cells count with S = 0; for Mars targets, Mars-gate failures leave the ranking, rule 8). **Blindness (review M2):** Moon metrics are blind; Mars metrics are post hoc, because the Mars gate was designed on this same set. `summary.by_body.{moon,mars}` reports them separately (`blind`, `note`) and `summary.headline_caveat` must accompany any pooled figure (developer-facing); `summary.headline_caveat_ui` (v1.2.1, additive) is the user-facing text the UI shows next to validation figures: "Moon results are a blind test: the scoring never saw these sites. Mars results are not blind, because the Mars dryness rule was designed using these same sites." Every evaluation has a `status`; gate-, land-filter- and hard-filter-excluded evaluations stay in all denominators as misses and are also listed separately in the summary. Metrics: % of positive evaluations in the Earth top 5% and top 1%, rank-AUC of positives vs negatives per (target, profile), averaged. Coastal sites (v1.2): a site whose own cell is not land is **snapped to the nearest ≥ 50% land cell within 1 cell** (8 neighbours, great-circle distance from the site to the cell centre); `eval_cell_id`, `snapped` and `snap_km` are recorded per site. `validation.json.frozen_commit` records the SHA of the commit that froze the method (v1.2 fixes landed) before the final validation run; weights were set before that freeze and are unchanged since v1.0. High-S sites > 300 km from any known analog are reported as "new candidate, needs field confirmation".

## 8. Fidelity gaps

`gaps.json` is Researcher's file (19 gaps): `never_on_earth` (6: partial gravity, hard vacuum, ionizing radiation, surface UV, lunar dust electrostatics, Mars CO₂ atmosphere), `beyond_earth_range` (5: lunar diurnal swing, PSR cryogenic cold, polar-ridge cold, Mars surface pressure, lunar polar low sun) and `coverable` (8). Each gap lists the factors it touches (`not_scored` for gravity, vacuum etc.), values with source URLs, facility types and example facilities (keys into `facilities`, 17 entries). The UI shows `never_on_earth` as a constant panel, `beyond_earth_range` as "best Earth / target / residual", and `coverable` gaps only inside the portfolio.
